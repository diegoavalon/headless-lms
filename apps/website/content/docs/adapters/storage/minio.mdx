---
title: S3-compatible storage
description: Store course assets in SeaweedFS or MinIO with the storage-minio adapter.
---

`@headless-lms/adapter-storage-minio` implements the `ObjectStorage` port for SeaweedFS, MinIO, and other S3-compatible stores. The bucket is private except its `public/` prefix, where the API publishes profile photos and the thumbnails and covers of published items for anyone to read. Every other file goes through short-lived presigned URLs, so the browser uploads and downloads directly against the store.

## Setup

Point the adapter at your store and inject it. The bucket is created if it doesn't exist, and on startup the adapter sets a bucket policy that lets anyone read `public/*` and nothing else.

```ts title="main.ts"
import { MinioStorageAdapter } from "@headless-lms/adapter-storage-minio";

const container = await createContainer(config, {
  adapters: { storage: new MinioStorageAdapter(storageConfig) },
});
```

The adapter reads no environment itself — your installation parses env into a `MinioStorageConfig` and constructs it.

For local development, Docker Compose starts SeaweedFS with an S3 endpoint on `:8006`. The reference installation's defaults match that setup. See [self-hosting](/docs/self-hosting).

When switching an existing checkout from the bundled MinIO service, copy any objects you want to keep into the same bucket and keys in SeaweedFS using an S3 client. SeaweedFS starts with a separate volume. Stop the old MinIO container before starting SeaweedFS on port `8006`.

## Environment variables

These are the variables the reference installation (`apps/api`) maps to the adapter's config:

| Variable                | Required | Maps to               | Notes                                                                                     |
| ----------------------- | -------- | --------------------- | ----------------------------------------------------------------------------------------- |
| `STORAGE_ENDPOINT`      | yes      | `endPoint`            | Host only, no scheme.                                                                     |
| `STORAGE_PORT`          | yes      | `port`                |                                                                                           |
| `STORAGE_USE_SSL`       | yes      | `useSSL`              | `"true"` / `"false"`.                                                                     |
| `STORAGE_ACCESS_KEY`    | yes      | `accessKey`           |                                                                                           |
| `STORAGE_SECRET_KEY`    | yes      | `secretKey`           |                                                                                           |
| `STORAGE_REGION`        | yes      | `region`              |                                                                                           |
| `STORAGE_BUCKET`        | yes      | `bucket`              | Created private if missing.                                                               |
| `STORAGE_UPLOAD_EXPIRY` | no       | `uploadExpirySeconds` | Presigned upload lifetime. Default 300. Stray member uploads older than this are swept.   |
| `STORAGE_PUBLIC_URL`    | no       | `publicUrl`           | Origin serving `public/*`, such as a CDN. Default `http(s)://<endpoint>:<port>/<bucket>`. |

## Using a different store

Any S3-compatible service (AWS S3, Cloudflare R2, …) works with this adapter — set the endpoint, credentials, and region accordingly. For something else entirely, implement the `ObjectStorage` port from `@headless-lms/core/types` (`presignUpload`, `presignDownload`, `stat`, `copy`, `list`, `remove` and `uploadExpirySeconds`) and pass it in the `storage` slot. The credentials need to list the bucket, because the hourly sweep lists the member uploads prefix.
